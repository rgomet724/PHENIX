PHENIX - ACTIVATION DE LA SECURITE V23

IMPORTANT : cette version nécessite de remplacer 3 fichiers :
- server.js
- package.json
- public/index.html (ou index.html selon ton dépôt)

RENDER - VARIABLE OBLIGATOIRE
Ajoute dans Render > Environment :
SESSION_SECRET = une clé aléatoire d'au moins 32 octets.

Sur macOS, tu peux générer une bonne clé avec :
openssl rand -base64 48

Copie UNIQUEMENT le résultat dans la valeur SESSION_SECRET.
Ne mets jamais cette clé dans GitHub.

Après modification :
1. Envoie server.js et package.json à la racine du dépôt.
2. Remplace l'index utilisé par PHENIX dans public/.
3. Commit / push.
4. Render va réinstaller les dépendances et redéployer.

EFFETS DE LA V23
- cookie de session HttpOnly + Secure en production + SameSite Strict
- session renouvelée après authentification
- protection contre la fixation de session
- expiration après 1 h d'inactivité et 8 h maximum
- protection CSRF sur les actions authentifiées
- limitation du brute-force sur la connexion
- limitation générale des appels API
- en-têtes de sécurité Helmet / HSTS / anti-frame / no-sniff
- API non mise en cache
- mot de passe de 12 à 72 caractères pour les nouveaux mots de passe
- bcrypt renforcé à 12 rounds pour les nouveaux mots de passe
- erreurs serveur génériques côté utilisateur
- suppression de l'en-tête X-Powered-By

NOTE :
Les anciens mots de passe continuent de fonctionner. La règle des 12 caractères s'applique lors de la création ou du changement d'un mot de passe.
